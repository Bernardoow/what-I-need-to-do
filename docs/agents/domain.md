# Documentação de domínio

O projeto tem um contexto. Leia `GLOSSARY.md` e os ADRs relevantes em `docs/adr/` antes de trabalhar no domínio. Use o vocabulário do glossário em tickets, propostas e testes. Ao identificar conflito com um ADR, cite a decisão e explique por que reabri-la. Use `domain-modeling` para registrar termos e decisões consolidados.
